# Native Pi / Termux verification — 2026-09-19

Environment: ARM64 Cuttlefish Android 17 (`CP2A.260605.016`), Termux 0.118.3,
Node 24.18.0, Pi 0.85.1, native Android Chromium 156.0.8067.0 (official snapshot
1701383). The adapter and Pi run as the Termux application UID; no root filesystem
access, proot, Rust runtime, Pi patch or custom Android picker is used.

## Automated native integration

`node --test tests/termux/*.test.mjs` passed **5/5** on Android (16.98 seconds)
and on the ARM64 Linux host with Node 22.23.2 (12.05 seconds).
Install `ripgrep` and `fd` alongside Node before running these tests. Test folders
are created inside the user's home and removed afterward.

- Actual Pi RPC with native read, write, edit, bash, grep, find and ls calls.
- Streaming thinking, assistant text and tool events; native usage/history.
- Native image payloads, multipart attachments and decoded clipboard-image data.
- Follow-up FIFO with edit holds, rename, fork, cwd changes at idle boundaries,
  compaction, stop/draft recovery, and web-server restart during an active turn.
- Web authentication, CSRF/origin rejection, native service API-key storage/logout.
- Native OAuth loopback server, invalid-state rejection, matching callback,
  PKCE challenge/verifier, credential persistence, cancellation and logout.
- Writable home-only folder selection, hidden unreadable/unwritable directories,
  safe file upload/download, sandboxed HTML, path confinement and backend ZIP.

The model is a deterministic local HTTP fixture in `tests/termux/mock-provider.mjs`.
The agent, tools, queues and session files are real Pi. No paid model response or
live subscription authorization is claimed.

## Android browser checks

ADB forwarded the device's localhost server and Chrome DevTools for Playwright
control of **the native Android Chromium app**, not a desktop approximation.
Android's own DocumentsUI and download dialog were operated on the device.

| Action | Result |
| --- | --- |
| Open `http://127.0.0.1:3939` and authenticate | Passed |
| Native Pi read tool, streamed work trace, collapsed/expanded thinking | Passed |
| Touch `⋯` menu, rename chat | Passed |
| Folder picker starts/stops at `~`; header shows `~/project` | Passed |
| Only writable home folders; no shared-storage/system-parent choices | Passed |
| Upload text file through browser → Android DocumentsUI | Passed; bytes verified in Termux |
| Attach image through the browser's normal file picker | Passed; native Pi receives image |
| Copy image in Android Chrome, paste via Android clipboard, send | Passed; native Pi receives image |
| Open image viewer and zoom | Passed |
| Expand repository directories and open file panel | Passed |
| Download whole repository ZIP | Passed; browser's download dialog saved archive to Downloads; archive entries verified |
| Pi API-key prompts entirely in Services | Passed with disposable test key, then logged out |
| Pi browser OAuth tab → native localhost callback → Connected | Passed with fixture token exchange, then logged out |
| Mobile viewport at 360 CSS pixels | No horizontal overflow; projects/files use drawers |
| Wide Android display at 1280 CSS pixels | Simultaneous project/chat/file columns: 260/720/300 pixels |

The wide check used Android's reversible display-size/density override. Both
were reset afterward. CDP viewport emulation alone is not reliable for native
Android layout and was not used as evidence for the wide result.

For OAuth, a browser route substituted a local fixture redirect for the provider's
authorization response, while Pi's unmodified callback server received that
redirect inside Android. A test-only preload (`BASHKITTEN_TEST_OAUTH=1` plus
`--import=tests/termux/oauth-token-fixture.mjs`) substituted the token endpoint.
This verifies the browser/Termux handoff without account credentials. A normal
launch does not load that fixture and opens the real provider authorization page.

During automation Chromium's in-memory Blob service stalled, including a minimal
`new Blob(['text']).text()` outside the app. Restarting Chromium recovered it.
The final real Android clipboard check passed. Clipboard reads now also have a
bounded timeout and preserve the draft if the browser cannot read an item.
